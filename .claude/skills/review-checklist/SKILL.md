# Review checklist

A brief can be well-written and still be missing the handful of things that
make it actually usable: who's accountable for it, what "done" looks like,
whether it stays about the same thing all the way through, and whether the
reader understands the problem before being told the answer. This skill
checks a document for exactly those four things — nothing else. It's a
sanity check, not a full edit.

## When the student points you at a file

Read the whole file first. Then check it against each of the four items
below, in order. For each one, decide **Pass**, **Partial**, or **Missing**,
and back that call with the actual evidence — a quoted line, a section
name, or a plain description of what's missing. Don't guess or round a
"maybe" up to a Pass; if you're not sure, call it Partial and say what
would make it a clean Pass.

### 1. Names who owns it

Look for someone explicitly accountable — a named person, a role, an
"Owner:" line, a "Decisions we need from X" section, or an equivalent. A
list of people mentioned in passing doesn't count; someone has to actually
be on the hook for the document or the decision it's asking for.

- **Pass**: a specific person or role is named as the owner or the
  decision-maker.
- **Partial**: people are named, but it's unclear who actually owns the
  call — e.g. three names with no indication which one decides.
- **Missing**: no owner anywhere in the document.

### 2. Says how we'll know it worked

Look for a success measure specific enough to actually check later — a
number, a date, a threshold, a before/after comparison. "We'll know it
worked when it works" or "this will improve things" doesn't count; there
has to be something a reader could come back to in six weeks and verify.

- **Pass**: a concrete, checkable measure of success.
- **Partial**: there's a stated goal, but no number, date, or way to
  verify it.
- **Missing**: no mention of how success would be recognized.

### 3. Keeps the same scope from start to finish

Read the whole document as one piece and check whether the problem
statement, the data, and the recommendation are all about the same thing.
Scope drift looks like: the opening describes a problem affecting one
group but the data covers a different group; the exec summary promises X
but the decisions section asks for Y; a section quietly broadens or
narrows who or what this is about without saying so.

- **Pass**: the subject stays consistent throughout — same people, same
  problem, same boundaries, start to finish.
- **Partial**: mostly consistent, with one section that drifts and should
  be reconciled or explained.
- **Missing**: the document is visibly about two different things stitched
  together.

### 4. Explains the problem before the fix

Check the actual structure, not just whether a "problem" section exists
somewhere. A reader working through the document in order should
understand *why* something needs to happen before they're told *what* to
do about it. A brief that opens with the solution and backfills the
reasoning afterward fails this even if all the right content is in there
somewhere.

- **Pass**: the problem (or the finding, or the "why") comes first, and
  the fix follows from it.
- **Partial**: both are present but interleaved in a way that's hard to
  follow in order.
- **Missing**: the fix is presented with no explanation of the problem it
  solves, or the problem never gets explained at all.

## Reporting back

Use this exact structure. Keep the evidence column short — a quote or a
pointer to a section, not a paragraph.

```
## Review checklist: <file name>

| # | Check | Result | Evidence |
|---|---|---|---|
| 1 | Names who owns it | Pass / Partial / Missing | <quote or note> |
| 2 | Says how we'll know it worked | Pass / Partial / Missing | <quote or note> |
| 3 | Keeps the same scope start to finish | Pass / Partial / Missing | <quote or note> |
| 4 | Explains the problem before the fix | Pass / Partial / Missing | <quote or note> |

**N of 4 pass.** <one line on the single most important thing to fix, if anything didn't pass>
```

If all four pass, say so plainly and don't invent extra nitpicks to seem
thorough — a clean pass is a real, useful result on its own.

## What this skill is not

It doesn't rewrite the document, check facts or numbers for accuracy, or
grade the writing quality. It only checks for these four structural
things. If the student wants more than that, say what this checklist
doesn't cover rather than quietly doing more.
